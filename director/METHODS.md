# Рабочие методики директора

Дата отбора: 14.11.2026. Это оригинальная рабочая инструкция для Midnight Dancer; сторонние пакеты целиком не копировались, глобальная установка не заявляется.

## 1. Конкурентная разведка

Начинай с вопроса решения: что может изменить наш выбор? Сравни прямые practice-apps и заменители: обычный плеер, папки, YouTube, CapCut, заметки преподавателя. Для карточки фиксируй продукт и разработчика, платформу/регион, сценарий, ключевые функции, free/paid границу, источник цены и дату. Не путай одноимённые приложения. Непроверенное поле — unknown.

Различай наблюдаемое, вывод и последствие для нас. «Не найдено на просмотренной странице» не означает «функции нет». Для заявления об изменении нужны два датированных состояния или changelog.
Источник методики: [Corey Haines — competitor-profiling](https://github.com/coreyhaines31/marketingskills/blob/main/skills/competitor-profiling/SKILL.md), прочитана 14.11.2026.

## 2. Пользовательские задачи

Исследуй последний реальный случай тренировки: материал, цель, что человек делал, где прерывался, чем заменял инструмент. Отдельно записывай ученика, преподавателя, постановщика. Отзыв — свидетельство конкретного автора, не доля рынка. Считай независимые случаи и сохраняй противоречия. Не публикуй исходные личные интервью в Git.
Источник: [Corey Haines — customer-research](https://github.com/coreyhaines31/marketingskills/blob/main/skills/customer-research/SKILL.md), прочитана 14.11.2026.

## 3. От проблемы к проверке

Для каждой идеи связывай желаемый результат, проблему, варианты решения и проверку рискованного предположения. Предложи альтернативы прежде дорогой разработки. Проверяй конкретное поведение, а не только ответ «нравится».
Источник: [Teresa Torres — Opportunity Solution Trees](https://www.producttalk.org/opportunity-solution-trees/), просмотрена 14.11.2026.

## 4. Стратегический разбор

Для крупного изменения последовательно оцени поле игроков, продуктовые различия, удовлетворение задачи, бизнес-модель, позиционирование и возможное направление конкурентов. Не превращай каждый ежедневный бриф в полный стратегический отчёт.
Источник: [Dean Peters — competitive-analysis-process](https://github.com/deanpeters/Product-Manager-Skills/blob/main/skills/competitive-analysis-process/SKILL.md), просмотрена 14.11.2026.

## 5. Правила Midnight Dancer

Собственные операционные правила, основанные на ресурсе владельца и текущем контексте:
- P0 — блокер текущей согласованной проверки/ценности; P1 — ближайшее улучшение после неё; P2 — исследовательский резерв. Рекомендация не меняет приоритеты разработки.
- Сначала качественная проверка на малой выборке, затем количественный эксперимент при достаточном трафике. 3 из 5 — критерий маленького теста, не доказательство рынка.
- Кандидат метрики пользы: уникальные пользователи с завершённой полезной тренировкой за 7 дней. Определение завершения и событий согласовать по готовой сборке; текущие значения неизвестны.
- Отдельно измерять активацию, возврат к тренировке, оплату/продление, возвраты и расходы. Установки не заменяют пользу.
- Для сайта фиксировать одну аудиторию, одну задачу и одно главное действие; не обещать недоступную платформу или функцию.
- Новый продукт получает карточку: покупатель, задача, альтернативы, доказательства спроса, синергия с ядром, обслуживание, деньги, минимальный тест, условие закрытия. Нет основания — оставить в резерве.
- Любой эксперимент планировать вместе с поддержкой и продажами в пределах 60–90 минут владельца в день.
